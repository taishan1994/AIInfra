Frontier Intelligence, Flash Cost

01 · TL;DR

不是单纯的“小模型”，而是高效的稀疏激活系统

GLM-5.3-Flash 的核心路线是“用更少的每 token 计算，保留更大的模型容量”。它把稀疏激活、线性/稀疏混合注意力、原生视觉能力和软硬件协同服务组合起来，目标是在 agent 长任务和百万上下文场景下同时降低成本、延迟与显存压力。

03 · ARCHITECTURE

混合注意力：局部状态 + 全局检索

混合架构不是把所有 token 都做昂贵的全局 attention，而是让线性注意力承担局部建模，稀疏注意力负责找全局证据。

在 1M 上下文下，稀疏 attention 的 indexer 本身也可能成为瓶颈，因此文章引入 IndexPool：将 4 个 indexer key vector 通过加权 pooling 压缩为 1 个，降低索引计算和内存开销。

工程上最重要的信号：长上下文优化不能只看 attention FLOPs，还必须同时优化 index、KV cache、带宽和调度。
04 · NATIVE MULTIMODAL

视觉不只是识图，而是进入 coding loop

GLM-5.3-Flash 将视觉能力放进 agent 的闭环，而不是只把图片作为一次性输入。对于前端开发、图表理解、文档和桌面操作，模型可以判断“什么时候需要观察”，再用视觉反馈修正下一步动作。

视觉反馈把“代码正确”扩展成“用户看到并操作起来也正确”。

06 · SERVING

面向国产 AI 芯片的 EPD 解耦服务

EPD 将 Encode、Prefill、Decode 放进独立、可调度、可扩展的 worker pool。

文章还提到 SGLang 推理引擎、TP、ReplaySSM、W8A8 量化、INT8/FP8/BF16 cache 量化和 Layer Split。相较同硬件基线，端到端 serving 性能提升约 3 倍，说明模型架构和推理基础设施必须协同设计。

07 · ENGINEERING TAKEAWAYS

对 AI Infra 的四点启示

  1. 稀疏激活只是第一层。真正的成本还包括 KV cache、indexer、通信、带宽和调度。
  2. 长上下文要做分层优化。线性 attention、稀疏检索、IndexPool 和 cache quantization 应联合评估。
  3. 多模态 agent 必须可观测。需要记录模型何时截图、看到了什么、为什么决定再次操作。
  4. 服务架构应围绕硬件瓶颈拆分。EPD 解耦让不同阶段按负载独立扩缩容，更适合异构和国产芯片集群。
GLM-5.3-Flash 的价值不只是“更便宜的 frontier model”，而是一套从模型结构、数据、视觉反馈到 serving hardware 的联合优化范式。
