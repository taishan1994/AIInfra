# 论文 Markdown 解读

当用户提供论文链接并要求“解读、总结、补充、生成 Markdown”时使用本 Skill。

## 目标交付物

生成一份可直接阅读和提交到知识库/仓库的中文 Markdown，至少包含：

- 论文基本信息、研究问题和一句话结论；
- 方法、架构、训练流程或系统流程的细化解释；
- 关键公式：定义符号，并用直观例子解释公式如何工作；
- 论文中的主要图和表，按正文出现顺序放在相关章节，不要集中堆在文末；
- 每张图说明“图中展示什么、如何读、支持什么结论”；
- 每张表同步论文原始数据或完整可读的关键数据，并说明比较维度、指标含义和结论；
- 实验设置、消融、局限、复现注意事项和面向用户场景的工程启示；
- 原文、代码、模型或数据链接（如果论文提供）。

## 工作流程

1. 先打开论文摘要页和正文 HTML；如果没有 HTML，再下载 PDF，并以论文当前版本为准。核对标题、作者、日期、版本、发表状态和摘要，不直接相信用户提供的二手总结。
2. 统计正文和附录中的 Figure/Fig.、Table/TABLE、公式和实验章节。建立“编号 - 原始文件 - 正文解释位置”的清单，避免漏图、漏表或重复插图。
3. 优先下载 arXiv source/e-print 或官方仓库中的原始图片和表格源文件。图片优先使用 source 中的 PNG/JPG/SVG/PDF figure；若源图是 PDF，可将单独的 figure PDF 转成 PNG/SVG，但不能裁剪整页论文截图作为最终图片。
4. 只把需要展示的图片复制到文章目录的 `assets/`，使用稳定、语义化的文件名。不要把论文 PDF、source tar、编译临时文件或整页截图加入交付物。
5. 表格应从 LaTeX/HTML/CSV 等源数据还原为 Markdown 表格。保留原始列名、单位、样本规模、百分比、小数和缺失值含义；表格太宽时可拆成多个逻辑表，但不能只写“见原文”。
6. 撰写 Markdown 时使用“解释 - 原图/原表 - 解读”的顺序。不要只贴图片；图片和表格必须紧邻对应解释。对于用户已有的结论，标注哪些是论文原文结论，哪些是基于实验的工程推断。
7. 若用户指定仓库目录，写入该目录并按仓库已有命名和链接风格更新索引 README；若未指定目录，先在当前工作区创建以论文 slug 命名的目录。默认不上传 GitHub，除非用户明确要求。
8. 完成后检查：所有 Markdown 图片路径存在、没有引用整页截图、所有 Figure/Table 编号都出现且只出现一次、公式符号前后一致、README 链接没有编码错误。

## 推荐 Markdown 结构

```markdown
# 论文标题
> 基本信息与原文链接

## 一句话结论
## 1. 背景与问题
## 2. 核心方法
### 2.1 架构/流程
### 2.2 公式与训练目标
## 3. 图表逐项解读
## 4. 实验与消融
## 5. 工程落地
## 6. 局限与复现
## 总结
```

图表段落示例：

```markdown
### Figure 2：训练流程

先解释读图方式和各阶段输入输出。

![Figure 2](assets/figure-02.png)

**图解：** 说明每个模块、箭头和颜色的含义，以及它如何支持论文结论。
```

## 重要边界

- 不把 PDF 页面截图当作论文原图；整页截图只能用于临时核对，不能提交。
- 不凭摘要猜测表格数值；表格数据必须来自正文、附录或论文源文件。
- 不把模型卡、新闻稿或用户总结中的 benchmark 数值冒充论文实验结果。
- 不为“生成 Markdown”默认执行 Git push、发布版本或删除用户文件；这些动作只有在用户明确要求时执行。
- 对尚未稳定的论文状态、发表信息、版本和外部链接使用联网核对，并在文中保留可追溯来源。
