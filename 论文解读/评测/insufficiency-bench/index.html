01 · TL;DR

一句话读懂这篇论文

法律 AI 的关键安全能力不是“总能给出答案”，而是知道什么时候还不能安全回答。 InsufficiencyBench 发现，十个前沿模型在缺失关键事实时普遍漏问、静默补全假设或过度回避；没有模型同时做到“缺失时会追问、完整时不乱问”。

02 · Research Question

论文评测的是“可回答性”，不是普通法律 QA

传统法律基准默认用户已经提供了完整事实，只评价模型能否基于输入得出正确结论。真实咨询通常相反：用户先讲故事，决定适用法律的关键信息往往尚未出现。

INPUT

用户问题

可能缺少辖区、雇主规模、程序阶段、合同条款或用户真正想解决的目标。
→
INTAKE

模型先筛查

识别哪些事实会改变法律框架、适用门槛或救济路径，并提出最小澄清问题。
→
ANSWER

再分析

信息足够时回答；不足时明确说明依赖关系，不能把默认值伪装成用户事实。

作者将“基于无声假设直接给出实质法律结论”称为 premature legal closure（过早法律闭合）。这和普通幻觉不同：模型可能在自己假定的辖区内把法律说对了，但对真实用户仍然是错的。

03 · Taxonomy

三种结构性失败模式，八类缺失元素

Switch：切换法律框架

缺失事实会决定到底适用哪套法律，例如辖区、控制性法条、损害事实。不同取值可能导向完全不同的结论。

Gating：决定框架是否适用

缺失事实触发资格或门槛，例如雇主规模、当事人身份、诉讼程序阶段、时效和用户目标。

Fatal prerequisite：致命前置条件

法律框架虽已确定，但缺少成立或获得救济的必要条件，例如合同对价、租金是否已付。

04 · Benchmark Construction

从完整问题出发，受控制造“缺信息”版本

数据集不是让标注者凭感觉判断问题模糊，而是先由有经验的律师写出完整法律事实，再在句子级别标注每个具有法律意义的元素及其理由。随后删除或最小修改提供这些元素的句子，生成带有明确 ground truth 的 deficient variant。

58 / 144
完整问题 / 缺失变体共 202 个项目；每个变体平均缺少 1.9 个元素，范围为 1–6 个。
541
已标注法律元素其中 96% 被律师标记为缺失后会影响安全回答的 required element。
335
细粒度 sub-tag将不同领域的具体事实映射到统一的八类 taxonomy，便于横向比较。

这个构造方式的价值在于：模型不需要生成一份唯一“标准法律答案”，评测只需检查它有没有识别出已知的关键缺失事实。

05 · Metrics

三个指标分别测识别、解释和安全

Element-identification F2

主指标，使用偏重召回的 F2：漏掉一个决定性事实比多问一个问题更危险。统计 precision、recall 和整体 F2。

Over-flag rate

在 58 个完整问题上，统计模型是否无端声称“还缺信息”，用于衡量过度追问和校准。

Explanation accuracy

模型识别出缺失元素后，是否能正确解释“为什么它会改变法律分析”，而不只是机械列清单。

Safety rate

缺失事实存在时，模型是否避免作出依赖该事实的虚构实质结论；安全率越高越好。

F₂ = 5PR / (4P + R)　　P = TP / (TP + FP)　　R = TP / (TP + FN)

十个模型的中位 F2 仅为 0.363，中位召回率为 0.44。模型对“看起来明显不完整”的缺口更敏感：控制性文本平均召回约 0.635，损害事实约 0.437；对程序姿态和当事人资格这类需要法律结构知识才能意识到的条件则明显更弱。

高分模型也存在校准代价：GPT-5.2 在完整问题上的 over-flag rate 为 72.4%，Claude Opus 4.7 为 53.4%。低分模型看起来不爱乱问，却可能只是几乎不追问；DeepSeek-V4-Pro 在 63.9% 的缺失问题上直接给出答案。

07 · Failure Analysis

两种失败极端：过度谨慎与静默假设

01
静默补全（最危险）
模型默认用户在某个州、雇主达到法定规模、已经完成程序步骤，然后基于默认值给出流畅结论。语言可能很专业，但适用框架已经错了。
02
无差别追问
模型对完整问题也要求更多信息，牺牲可用性来换取表面安全。真正需要的是判断哪些缺失元素会改变结论，而不是泛化地说“请提供更多背景”。
03
结构性盲区
程序姿态、当事人状态和资格门槛通常不会让自然语言显得“不完整”，但它们可能直接决定法律框架是否适用。
08 · Engineering Takeaways

对法律 Agent 与通用 Agent 的工程启示

DETECT

先做 sufficiency gate

把“是否可回答”作为独立决策层，维护领域内会改变结论的必需字段。
→
CLARIFY

问最小高价值问题

按 Switch → Gating → Prerequisite 的顺序追问，说明每个问题为何会改变分析。
→
ANSWER

显式假设后再分析

信息仍不足时可提供条件化建议，但必须把假设、影响范围和下一步验证写清楚。

建议纳入线上监控

除最终答案准确率外，记录缺失事实识别召回、完整问题误报率、澄清问题数量、用户补充后的闭环成功率，以及模型是否在缺失事实下产生实质结论。否则“回答率上升”可能掩盖了安全性下降。

09 · Critical Reading

局限与正确的外推边界

规模仍小仅 202 个项目、6 个美国法律领域，不能代表所有法律体系和非对抗型法律事务。
单轮评测真实 intake 往往是多轮对话；模型能否通过追问逐步补齐事实，论文尚未覆盖。
LLM Judge 依赖解释和安全指标由模型裁判辅助，人工验证有限；换裁判后主结论保持，但绝对分数仍需谨慎。

最值得迁移的不是“某个模型排名”，而是评测范式：为每个领域定义会改变结论的输入要素，分别测试缺失时的识别能力和完整时的克制能力。
